# Graphify developer workflow

This repository supports [Graphify](https://github.com/Graphify-Labs/graphify) as an optional developer tool for building and querying a local knowledge graph of the codebase. Graphify is not an application dependency and is not installed or executed by the normal CI workflow.

The repository pins the supported CLI version in `.graphify-version`. The Python package is currently published as `graphifyy`, while the installed command is `graphify`.

## Prerequisites

- Python 3.10 or newer.
- `uv` is recommended for isolated CLI installation.
- An AI coding assistant is optional for code-only graph extraction. Graphify parses code locally with tree-sitter; semantic extraction for documentation or media can use an assistant/model backend, so review the corpus before including private or sensitive untracked material.

Install the exact repository-pinned version:

```bash
uv tool install "graphifyy==$(cat .graphify-version)"
```

If a different Graphify version is already installed with `uv`, reinstall the pinned version before regenerating the project skill:

```bash
uv tool install --reinstall "graphifyy==$(cat .graphify-version)"
```

Verify the CLI is available:

```bash
graphify --help
```

## Build and query the graph

The committed `just` recipes are thin wrappers around the locally installed CLI:

```bash
just graphify-build
just graphify-update
just graphify-query "how does tenant authorization reach persistence?"
just graphify-watch
```

They map to:

```bash
graphify .
graphify . --update
graphify query "<question>"
graphify . --watch
```

A normal build writes local generated state under `graphify-out/`. That directory is intentionally ignored by Git. Do not commit `graph.json`, `GRAPH_REPORT.md`, HTML output, caches, generated wiki pages, SVG/GraphML exports, or Neo4j output from normal developer runs.

Graphify also honors `.gitignore`. This repository adds `.graphifyignore` only for Graphify-specific exclusions. Implementation plans under `docs/superpowers/plans/` are excluded because they commonly describe transient execution state; approved design specs remain available to the graph as durable architectural context.

## Project Agent Skill

The generic project-scoped Agent Skill under `.agents/skills/graphify/` is generated by the official pinned Graphify CLI and committed so compatible agent frameworks can discover it without requiring a global Graphify skill installation.

Regenerate it only with the repository-pinned CLI:

```bash
graphify install --project --platform agents
```

Review every generated change before committing it. Do not hand-edit the generated `SKILL.md`, `.graphify_version`, or `references/` files; update `.graphify-version` and regenerate instead.

## Assistant-specific integrations are opt-in

The repository deliberately does not force assistant-specific always-on hooks or user-global configuration. Developers may opt into upstream integrations when they want assistant-specific behavior. Examples supported by Graphify include:

```bash
graphify install --project                 # Claude Code project integration
graphify install --project --platform codex
graphify install --project --platform opencode
graphify cursor install
graphify kiro install
```

Use the upstream `graphify --help` and Graphify documentation for the current list of platforms and exact platform-specific behavior before enabling an integration.

For Codex, Graphify's parallel semantic extraction can require this user-level setting:

```toml
[features]
multi_agent = true
```

That belongs in the developer's Codex configuration, not in this repository.

## Hooks are not defaults

This repository does not install any of the following automatically:

- Graphify always-on assistant hooks;
- strict source-read blocking hooks;
- `graphify hook install` post-commit hooks;
- assistant configuration that redirects normal source reads through the graph.

These behaviors can be useful for an individual workflow, but they affect editor/agent behavior and may be clone-local or user-global. Enable them explicitly only after reviewing the upstream behavior.

## MCP policy

MCP is not enabled by the initial repository integration. Graphify can expose an MCP server, but MCP configuration adds assistant-specific lifecycle and configuration concerns that are intentionally separate from the base CLI and project-skill integration.

Treat MCP as an explicit opt-in or a separate reviewed repository change. Do not add an MCP server to the normal application process or CI simply to support Graphify.

## Upgrading Graphify

Graphify upgrades are deliberate reviewed changes. Do not silently follow the latest release.

1. Update `.graphify-version` to the selected version.
2. Install exactly that version:

   ```bash
   uv tool install --reinstall "graphifyy==$(cat .graphify-version)"
   ```

3. Regenerate the generic project Agent Skill:

   ```bash
   graphify install --project --platform agents
   ```

4. Review the complete `.agents/skills/graphify/` diff, including `.graphify_version` and `references/`.
5. Run the repository verification gates (`just check` and the normal CI jobs).
6. Confirm `package.json`, `bun.lock`, and `.github/workflows/ci.yml` did not gain Graphify runtime/CI dependencies.

The repository pin is the compatibility contract; generated project-skill content should always correspond to that pin.
