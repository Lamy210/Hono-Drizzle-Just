# Test Factory Framework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the one-off user DB fixture function with a reusable typed build/persist factory foundation kept entirely under `tests/`.

**Architecture:** A generic build-only `TestFactory` owns sequence/default/override behavior. `PersistentTestFactory` adds an explicit async persistence function. Feature factories wrap these primitives and may accept a root or transactional `DatabaseSession`.

**Tech Stack:** Bun 1.4.2, TypeScript 7, Drizzle ORM 0.45.2, PostgreSQL 18, bun:test.

**Spec:** `docs/superpowers/specs/2026-09-13-test-factory-framework-design.md`

## Global Constraints

- Factory infrastructure stays under `tests/`; production code must not import it.
- Build-only factories must not expose database persistence methods.
- Default UUIDs must be real UUIDs generated by `crypto.randomUUID()`.
- Bulk persistence must preserve input/sequence order and must not imply atomicity.
- Relations remain explicit composition rather than hidden auto-persistence.
